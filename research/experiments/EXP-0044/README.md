# EXP-0044: Ryu's Ending in Official English (M7)

Task: END-010
Status: DONE (2026-10-24)
Confidence: CONFIRMED. A deterministic image built from the untouched source
shows Ryu's ending in official English on a cold boot, with Ken and with Gouki
as partner, verified live and pinned in the regression baseline.

## Hypothesis

An image compiled from the untouched source shows Ryu's ending with:
- the arcade's English pages in `ME.PAC`;
- the partner and point English lines in `MC13`'s pairs (16 + 2·index);
- English names, using quote-font pair glyphs (`FONT-003`).

It needs no other change.

Sub-hypotheses, tested one at a time before the build:
- **T1:** a blank record is skipped. (It is not; see below.)
- **T2:** `0x0000` inserts the name at any cell.
- **N:** the names come from a table that can be edited on disc.

## Actual Result

### Pre-build trials (RAM writes on the untouched image, `ryu_ken_post_boss_ko.mcs`)

- **T1** (Ken box 2, record 37, all `0x0020`): an **empty red box** shown for
  the full time (about 240 frames). It is not skipped, and the timing is
  unchanged. So every box of a pair needs text.
- **T2** (`0x0000` written at record 87, line 1 cell 5, which has no
  placeholder originally): the partner's name appeared at cell 5, and the
  following text shifted right. A placeholder works at any cell.
- **N.**
  - The name table is in `MM.BIN`: 32-byte entries from file `0x7D3C0` (slot 0
    to 25). `MM.BIN` is loaded raw at WRAM-H `0x06018B00`, so the table is at
    `0x06095EC0`.
  - V1, a cold boot of the built image: WRAM-H differs from the untouched
    image's boot in `MM.BIN`'s region only at the 16 name bytes.
  - 92 more bytes differ elsewhere (`0x06010A94`, `0x060EFA91…`), outside the
    program. These are presumably buffers; not investigated.
- **Safety.** No candidate (sacrificial) kanji is used by any Japanese ending
  page (the arcade page region equals `ME.PAC`'s) or by the `MC13` dialogue
  records. So neither this build nor the M5 roster image blanks ending text.

### Why a state replay is not enough

- Replaying `before_stage08_load.mcs` on the built image loaded the new `MC13`
  and `ME.PAC` (the RAM records equal the new files). But **every box and page
  was empty.**
- Cart RAM still held the **old** font: the quote font is loaded after boot
  (its pointer `0x0601D8E4` is 0 at the title) and stays resident. It is not
  reloaded at stage 8, so the new pair codes decoded to empty cells.
- The agent cannot write cart RAM (the `physical` space reads zeros there). So
  the live check needs a cold boot, with the user working the menus only.

### Live, cold boot of the built image

- **Run 1** (first build, track 01 `9cd4bb55…`), Ryu + Ken:
  - All four boxes and all three pages were English.
  - Box 1 read "RYU ," with **a blank cell before the comma**
    (`f00013384` `3b5d8978…`).
  - Cause: the game inserts a fixed number of cells per name, from a one-byte
    length table at `MM.BIN` `0x96DE8` (WRAM-H `0x060AF8E8`). All 26 entries
    equal the Japanese names' lengths. Ryu's is 3, but "RYU" is 2 pair cells.
    "KEN." had no gap: 2 = 2.
  - Fix: a `patches` entry setting slot 9's length to 2. Rebuilt track 01:
    `b481a4c6012288e8…`.
- **Run 2** (rebuilt), Ryu + Ken. The driver forced the KO at frame 7,466.
  The boxes read:

## Conclusion

**CONFIRMED (M7).** Ryu's ending is localized from the untouched source with
the official arcade English:
- the three pages;
- the two partner lines, for Ken and for Gouki;
- the English names.

The build is deterministic and regression-pinned, and it was verified live
from a cold boot for both partners.

**CONFIRMED mechanisms, new in this experiment:**
- a blank dialogue record is shown as an empty box, not skipped;
- `0x0000` inserts the name at any cell;
- the `MM.BIN` name table (`0x7D3C0`) and name-length table (`0x96DE8`) are
  loaded at boot;
- the quote font is loaded after boot and stays resident, so a state replay
  keeps the old font.

## Uncertainty and Alternatives

- **Partners covered:** only Ken and Gouki. With another partner, Ryu's ending
  shows that partner's Japanese boxes 1-2, then the English boxes 3-4 with
  that partner's Japanese name. Generalization belongs to `END-020`.
- **Side effect:**
  - Any other text that inserts a name (`0x0000`) now shows RYU, KEN, or AKUMA
    in this image. That includes the original Japanese win quotes with
    placeholders, and other teams' Japanese dialogue.
  - The lengths of KEN (2) and AKUMA (3) equal the Japanese ones. RYU's
    changed (3 → 2).
- **The forced KO.** It happens at round start, landed by the point character,
  as in the arcade route. The KO character's effect is untested (`EXP-0043`).
- **Not examined:** the 92 differing WRAM-H bytes after boot.
- **Separate images:** this image does not include the M5 roster win quotes.
  Combining them needs one shared spec. The candidate kanji are safe for
  endings (above).
