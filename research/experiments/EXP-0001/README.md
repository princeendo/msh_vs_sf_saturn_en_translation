# EXP-0001: Boot MSHvSF Saturn to a Normal Game Screen

Task: EMU-004
Status: DONE
Confidence: CONFIRMED

## Observation

`EMU-003` showed that stock Mednafen 1.32.1 opens the untouched MSHvSF Saturn
image, selects software ID `T-1238G`, selects `Cart: 4MiB Extended RAM`, and
initializes Saturn video and audio. That run ended before a normal game-screen
endpoint was observed.

## Hypothesis

With the same stock binary, project-local configuration, BIOS files, and
untouched source image, allowing the Saturn boot sequence to continue and
using the configured keyboard controls will reach a stable, visibly rendered
MSHvSF game screen.

## Controlled Change

Only the runtime observation and input sequence change. The Mednafen binary,
source image, BIOS files, project-local configuration, and launch command remain
unchanged from `EMU-003`.

## Prediction

The run will reach a stable MSHvSF title, menu, or gameplay screen rather than
remaining at emulator initialization or BIOS-only output. A screenshot will be
captured from that endpoint.

## Procedure

1. Verify the source-image component hashes against the tracked manifest:

   ```bash
   ./invenv.sh python -m tools.disc.hash_source \
     --description "EMU-004 source identity verification" \
     --json local/disc_images/mshvsf_saturn_jp/*
   ```

2. Verify the stock binary and canonical BIOS alias hashes:

   ```bash
   shasum -a 256 vendor/mednafen/build/src/mednafen \
     local/mednafen/firmware/sega_101.bin \
     local/mednafen/firmware/mpr-17933.bin
   ```
3. Confirm no prior Mednafen process is using the local runtime root.
4. Launch from the repository root with:

   ```bash
   MEDNAFEN_HOME="$PWD/local/mednafen" \
     vendor/mednafen/build/src/mednafen \
     "local/disc_images/mshvsf_saturn_jp/Marvel Super Heroes vs. Street Fighter (Japan).cue"
   ```

5. Focus the Mednafen window and use the configured Start and gamepad keys as
   needed to proceed through the Saturn boot/title flow.
6. Capture the first stable, visibly rendered MSHvSF game screen with the
   configured Mednafen snapshot command.
7. Record the screen description, screenshot filename, size, and SHA-256.
8. Exit Mednafen cleanly and verify the source-image component hashes again.

## Actual Result

The first run initialized the target and remained active while the title flow
was observed manually. It was closed before a snapshot action could be sent.
The second run used the identical launch command and reached the same target
initialization. Its log recorded:

```text
SGID: T-1238G
SGNAME: MARVEL SUPER HEROES VS. STREET FIGHTER
SGAREA: J
Cart: 4MiB Extended RAM
```

After the window was focused, the tested host control sequence sent Enter to
continue the title flow, waited three seconds, and sent the configured
Mednafen snapshot key. Mednafen created this endpoint evidence:

| Artifact | Size | SHA-256 | Description |
| --- | ---: | --- | --- |
| `local/mednafen/snaps/Marvel Super Heroes vs. Street Fighter (Japan)-0001.png` | 22616 bytes | `4c19283ec7c84b6b7690fa526e3323a7e0121efa75fa5fa9c6e88bf3c24f0d85` | 352x240 snapshot of the stable MSHvSF title screen and mode menu |

The retained second-run log is `local/mednafen/logs/emu004-launch-2.log`,
4190 bytes, SHA-256
`e3ff1139f0774d6bb34160d315f6d496386ff5cdf75c7e63564e7862224156f2`.
Mednafen then exited cleanly and no process or runtime lock remained.

## Conclusion

`CONFIRMED`: the selected stock Mednafen 1.32.1 build reaches a stable,
visibly rendered MSHvSF Saturn title screen from the recorded untouched source
image and project-local launch configuration. The result is reproducible for
the tested launch and input sequence. This confirms the EMU-004 boot endpoint
only; it does not independently verify every controller mapping or the
4 MiB-cartridge acceptance criteria.

## Uncertainty and Alternatives

The captured endpoint is the title screen, not gameplay. The run still reports
the unsupported CUE `CATALOG` directive and absent adjacent `.sbi`; boot
success means those warnings did not prevent this endpoint, but does not
establish that they are harmless for later experiments. The screenshot and
logs are ignored binary evidence; only their metadata is tracked.

## Reproduction

From the repository root, run:

```bash
MEDNAFEN_HOME="$PWD/local/mednafen" \
  vendor/mednafen/build/src/mednafen \
  "local/disc_images/mshvsf_saturn_jp/Marvel Super Heroes vs. Street Fighter (Japan).cue" \
  > local/mednafen/logs/emu004-launch-2.log 2>&1
```

With the Mednafen window focused, the tested host control sequence was:

```applescript
tell application "System Events"
  tell process "mednafen"
    key code 36
    delay 3
    key code 101
  end tell
end tell
```

Here `key code 36` is Enter and `key code 101` is the host F9 key that the
tested configuration assigns to Mednafen's snapshot command. Exit was tested
with host F12 (`key code 111`). Runtime binaries, screenshots, and logs remain
under ignored paths. This record stores only permitted metadata and hashes.
