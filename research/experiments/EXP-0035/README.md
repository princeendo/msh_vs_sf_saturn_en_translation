# EXP-0035: Deterministic 17-Character Official-English Roster Image

Task: RE-045
Status: DONE (offline). Live verification is `RE-046`.
Confidence: CONFIRMED (build, binary traceability, offline render)

## Observation

The `RE-044` roster spec fits one shared font: 338 pairs, of which 90 reuse kanji
codes, using 13,992 of 30,235 bytes.

## Hypothesis

`caption_compiler.py` builds the whole roster deterministically from the untouched
source. It changes only roster target cells, pair codes, and sacrificed or reused
glyphs, and every record renders as its paired official English.

## Controlled Change

One spec input: `local/re044/roster_official_en.json` (SHA-256 `b2c097fa…f334`),
generated by `tools/text/official_captions.py --roster data/text/m5_roster.json`
from `mshvsfu.zip`.

## Prediction

- Two builds are byte-identical, and every compiler check is true.
- Only the 17 roster `MCnn.PAC` files and `MEMFIX.PAC` differ.
- The blocks the register keeps untouched are byte-identical.
- The offline renders show every record's paired English legibly.

## Actual Result (2026-10-24)

- **Build.** `build/re045` (ignored).
  - Track 01 SHA-256
    `f5044e8ac6102de2333cb27076286f905e4324886b44653e3e694442d46bb6d2`;
    `MEMFIX.PAC` `f60e512f…045a`.
  - `image_a` and `image_b` are identical (`cmp`; manifest
    `builds_identical: true`). There are 184 changed sectors.
  - Image checks: 0 bad sync, 0 address mismatches, 0 invalid EDC/ECC. Of 414
    files, the 18 that differ are `MC01`-`MC10` (except `MC11`), `MC12`, and
    `MEMFIX.PAC`.
- **Font checks.** All true: header unchanged; changed codes = pair codes +
  sacrificed; pairs equal composed; sacrificed empty; non-reused pair codes were
  empty; reused codes in the kanji range.
  - 338 pairs.
  - 90 kanji codes reused and 57 more kanji emptied for bytes (147 of 321 unseen
    kanji).
  - 13,992 pair bytes; zero fill 17.
- **Tables.** For all 17 files, the decoded length and file size are unchanged
  and only target cells changed (676-1,038 decoded bytes each). Every file was
  spliced; no full re-encode was needed.
- **Exceptions untouched.** `MC02` slot 23 (`0xDF68`), `MC08` slot 24 (`0xBE5C`),
  and `MC0C`'s 4-record table (`0x3B88`) decode byte-identical to the original.
- **Records.**
  - In every roster table, record `k + 8` equals record `k`, as the policy
    requires.
  - No `0000` placeholder remains, matching the drop decision.
- **Offline render review.** All 17 `records-MCnn.png` were read. Records 0-7
  were checked by eye; 8-15 are byte-identical to them.
  - Every line is legible, centred, and keeps the arcade line break.
  - New glyphs read correctly in context: `'` (for example "don't"), `?`, `"`
    ("you can do it!"), `-` ("X-men", "web-"), and the one-cell `‼` ("stuff‼").
  - The arcade's own wording quirks are kept as official text.

## Conclusion

**CONFIRMED (offline).** The 17-character official-English roster image builds
deterministically, with fully traced binary changes and no collateral changes. It
is ready for live verification (`RE-046`).

## Uncertainty

- Not yet run on the Saturn. Runtime behavior is untested for the 15 new
  characters; Ryu and Ken were proven earlier.
- 147 kanji are now empty or replaced. Text outside the win-quote census
  (endings, other formats) could need some of them (`EXP-0023` limitation).

## Reproduction

```bash
./invenv.sh python -m tools.text.official_captions --driver /tmp/cps2.cpp --archive local/arcade_roms/mshvsf/mshvsfu.zip --roster data/text/m5_roster.json --out local/re044/roster_official_en.json
```

```bash
./invenv.sh python -m tools.text.caption_compiler local/re044/roster_official_en.json --out-dir build/re045
```
